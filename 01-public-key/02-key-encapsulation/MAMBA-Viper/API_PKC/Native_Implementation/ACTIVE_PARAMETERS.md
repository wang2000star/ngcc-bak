## Active length convention

- FO message bits = shared key bits.
- FO message bytes = shared key bytes.
- z bits = shared key bits.
- z bytes = shared key bytes.

## Size formulas

- `pk_bytes = 32 + k * n * t_pk / 8`.
- `ct_bytes = 32 + k * n * t_u / 8 + n * t_v / 8`.
- `secret_key_bytes = k * n * q_bits / 8`.
- `hpk_bytes = 32`.
- `z_bytes = ss_bytes`.
- `sk_bytes = secret_key_bytes + pk_bytes + hpk_bytes + z_bytes`.
- `ss_bytes = target / 8`.

## Benchmark result policy

The single canonical benchmark output is `scripts/results/viper_benchmark_results.csv`. Full benchmark runs overwrite this CSV at the beginning and append all measured rows during the same run. Legacy root-level files such as `viper_e8_codec_bench_results.csv` and `viper_scalar_profile_bench_results.csv` are obsolete and should not be generated by default. Scalar-profile and E8-codec benchmark rows that are still useful should be written as rows in the canonical CSV, not as separate root-level CSV or markdown report files.

`viper_power2_security_estimates_by_cost_model.csv` is retained as diagnostic/archive-style estimator output and is not the active parameter definition.
