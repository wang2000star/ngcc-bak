# NTRE Optimized Implementations

This directory contains the optimized NTRE KEM implementation packages.

## Layout

* `1_算法源代码/`

  x86_64 AVX2-oriented optimized implementations for `NTRE-128`, `NTRE-256`, and `NTRE-512`.

  These packages keep the same NGCC KEM API as the reference implementations. The current optimized code uses the documented optimized build profile and an AVX2 assembly layer for small polynomial arithmetic hot paths. NTT, inverse NTT, base multiplication, packing, CBD, and mod-2 decode still use the audited C code path.

Each instance provides:

* `KEM_AlgorithmInstance.c` and `KEM_AlgorithmInstance.h`
* NGCC fixed support files: `KAT_KEM.c`, `auxfunc.*`, `drng.*`
* NTRE-specific arithmetic and symmetric-code files under `src/`
* `Makefile`
* `test/`

## Build

From an instance directory:

```sh
make clean all
make test
make kat
```

Some Makefiles only build the test binary when `make test` is invoked from the instance directory; run the produced test executable if the Makefile does not execute it automatically.

## Optimized Build Profile

The optimized implementation uses the documented optimized build profile:

```sh
gcc -O3 -march=x86-64 -mavx2 -mtune=native -flto \
    -fomit-frame-pointer -std=c99 -Wpedantic -Wall -Wextra \
    -Wno-unused-parameter -Wno-unused-result
```

This profile enables AVX2 support, link-time optimization, native tuning, and frame-pointer omission for the optimized x86 implementation.

## Performance Records

Self-evaluation performance records are stored in:

```text
2_自评估代码和数据/Benchmark_Results/
```

The benchmark script is stored in:

```text
2_自评估代码和数据/scripts/run_ntre_benchmarks.sh
```

The benchmark script measures all three NTRE instances through the NGCC `kem_*` API and records both:

* NGCC document profile: reference `gcc -O2` versus optimized `gcc -O3` with AVX2, LTO, native tuning, and frame-pointer omission.
* Same-flags sanity profile: both implementations built with the optimized flags, to separate compiler-option effects from source-level differences.

Related result files include:

* `ntre_optimized_before.csv`
* `ntre_optimized_before.log`
* `ntre_optimized_after.csv`
* `ntre_optimized_after.log`
* `ntre_optimized_summary.md`

## Generated Files

The following are build or generated test artifacts and should not be kept in the source package:

* `bin/`
* `output/`
* `test/test_ntre`
* object files and other compiler outputs

Test vectors intended for delivery should live outside this source tree, for example in:

```text
1_源代码/Test_Vectors/
```
