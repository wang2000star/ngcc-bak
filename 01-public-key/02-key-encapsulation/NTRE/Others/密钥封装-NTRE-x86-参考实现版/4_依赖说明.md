# NTRE Reference Implementation Dependency Statement

This document describes the dependencies and build requirements of the NTRE reference implementation package.

## 1. Package Scope

This package contains the portable reference implementations of the NTRE Key Encapsulation Mechanism.

The included NTRE instances are:

* `NTRE-128`
* `NTRE-256`
* `NTRE-512`

Each instance provides the standard KEM operations:

* `KeyGen`
* `Encaps`
* `Decaps`

The implementations keep the NGCC KEM API used by the submission package.

## 2. Directory Layout

The reference implementation source code is stored in:

```text
1_算法源代码/
```

The expected layout is:

```text
1_算法源代码/
├── NTRE-128/
├── NTRE-256/
├── NTRE-512/
└── README
```

Each instance provides:

* `KEM_AlgorithmInstance.c`
* `KEM_AlgorithmInstance.h`
* NGCC fixed support files:

  * `KAT_KEM.c`
  * `auxfunc.*`
  * `drng.*`
* NTRE-specific arithmetic and symmetric-code files under `src/`
* `Makefile`
* `test/`

## 3. Programming Language

The NTRE reference implementation is written in C and follows the ISO C99 standard.

No C++ runtime is required.

## 4. Build Dependencies

The reference implementation requires a standard Linux C build environment.

Required tools include:

* `gcc`
* `make`
* `bash`
* `coreutils`

The implementation does not require external mathematical or cryptographic libraries.

In particular, it does not depend on:

* OpenSSL
* GMP
* NTL
* FLINT
* libsodium

Only the standard C library and the system build toolchain are required.

## 5. Recommended Build Profile

The reference implementation is intended to be compiled with the following profile:

```sh
gcc -O2 -std=c99 -Wpedantic -Wall -Wextra \
    -Wno-unused-parameter -Wno-unused-result
```

The options `-Wno-unused-parameter` and `-Wno-unused-result` are used for compatibility with the provided template and test harness. They do not change the algorithmic behavior of the implementation.

## 6. Build Instructions

From an instance directory, for example:

```sh
cd 1_算法源代码/NTRE-128
```

run:

```sh
make clean all
make test
make kat
```

The same procedure applies to:

```text
1_算法源代码/NTRE-256/
1_算法源代码/NTRE-512/
```

Some Makefiles only build the test binary when `make test` is invoked from the instance directory. If the Makefile does not execute the test binary automatically, run the produced test executable manually.

## 7. Randomness and KAT Support

Each instance includes deterministic random generation support files:

```text
drng.c
drng.h
```

These files are used by the KAT and test programs to generate reproducible test inputs and outputs.

Known-answer test vectors intended for delivery should live outside the source tree, for example in:

```text
2_自评估代码和数据/Test_Vectors/
```

## 8. Generated Files

The following files and directories are build or generated test artifacts and should not be treated as source files:

```text
bin/
output/
test/test_ntre
*.o
*.a
```

They may be removed by running:

```sh
make clean
```

## 9. Reference Implementation Notes

This dependency statement applies only to the NTRE reference implementation.

The reference implementation is portable C99 code. It does not use x86-specific assembly code, AVX2-specific vectorized code, or other performance-oriented implementation dependencies.

Performance-optimized implementations, benchmark scripts, benchmark results, self-evaluation reports, and test vectors are provided separately in the corresponding submission directories.
