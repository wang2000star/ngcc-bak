# 青鸾 v2 安全性论证(QingLuan v2 Security Argument)

> 本文档对应实现计划 **Task 7.1**:EUF-CMA 论证 + 具体安全表 + **哈希用途的 TCR/原像归约义务**。
> 它是 `protocol_reference.md`(协议契约)与 `parameters.md`(参数与估算)的安全侧综合,
> 论证对象是当前 `../Implementations/Reference_Implementation/QingLuan-*/src/` 的实现。本论证为**人工论证文档**,非机检证明(见设计 §1.3)。

## 0. 摘要与本次论证发现

青鸾 v2 是基于 **R-SDP + MPC-in-the-Head + Fiat–Shamir** 的数字签名,对称原语全用 **SM3**(GB/T 32905)。
本论证给出:(1) ROM/QROM 下的 EUF-CMA 论证;(2) 杜绝 v1"仅凭公钥通用伪造"的结构性根因;(3) **逐一**把每处哈希用途归约为 SM3 的(第二)原像 / 目标抗碰撞(TCR/eTCR),证明"不可约依赖朴素抗碰撞"的用途集合为**空**;(4) 各等级具体安全达标且有冗余的复核表。

> **★ 本次论证发现并修复的一个安全缺陷(设计风险 R1 的实例,已闭环):**
> 论证过程中(§3)发现实现的**消息绑定哈希 `digest_Msg` 此前未加盐**(`Hash(DOMAIN_MSG | pk_hash | Msg)`),
> 与设计 §4.2 规定的 `μ = H_w(DOMAIN_MSG ‖ r ‖ pk ‖ M)`(含每签名随机化子 `r`)**不符**。
> 由于 `H_w` 是多管道 SM3,其**朴素抗碰撞被 Joux 多碰撞封顶在 ~`2^128`(与输出宽度无关)**,一个 ~`2^128` 的消息碰撞
> 可把签名从 `Msg` 转移到 `Msg′`,从而把 EUF-CMA **封顶在 `2^128`,使 QingLuan-256/384/512 达不到其经典目标**。
> **修复:** 将每签名 `Salt` 作为随机化子折入消息哈希:`digest_Msg = H_w(DOMAIN_MSG | Salt | pk_hash | Msg)`
> (提交见 `git log`;代码 `src/mpc.c::mpc_digest_msg`,调用方 `sign.c`/`verify.c`)。这把消息绑定从"朴素抗碰撞"
> 转为"**多目标 eTCR / 第二原像** = `2^{2λ}`",**无需** SHAKE 回退,方案保持纯 SM3。修复后四等级正确性、伪造门禁、
> 确定性全部回归通过(见 §6.3 / `test/`)。

## 1. 方案、安全目标与威胁模型

- **方案:** `crypto_sign_keypair / signature / verify`(NIST 风格)+ `crypto_sign / sign_open`。协议见 `protocol_reference.md`(转录自 CROSS-RSDP NIST round-2 规范并标注青鸾的国密实例化偏差)。
- **目标安全性:** 在随机预言机模型(ROM)及量子可访问随机预言机模型(QROM)下满足 **EUF-CMA**(选择消息攻击下的存在性不可伪造)。
- **威胁模型(对齐《算法技术要求》第 2 节(2)):**
  - 攻击者可发起 **`≤2^80` 次签名/解封装询问**(《技术要求》(2)明示的询问次数上界;多目标第二原像分析的**目标数即取此 `2^80`**,见 §3.3);
  - 攻击者可发起 **`≤2^80` 次哈希(随机预言机)询问**;
  - 经典与量子两种算力;量子下对搜索施加 Grover 平方根加速(保守)。
  - **概念澄清:** 此 `2^80` 是**询问预算**,与下方“量子安全下限 80”是**两个不同的量**——后者是 128 级的**等级定义**(NIST 类别 1 / AES-128 口径),并非由 `2^80` 询问推得;勿混淆。
- **等级要求:** 经典 128/256/512(+可选 384),量子 ≥80/128/256(+192);均留冗余。256/384/512 量子下限 = 经典/2;**128 级量子下限 80 系等级定义(NIST 类别 1)**,见 §4 注①。

## 2. EUF-CMA 论证

### 2.1 底层识别协议(CROSS-ID,R-SDP)

秘密 `e ∈ E^n`(`E=⟨2⟩⊂F_127^*`,`|E|=z=7`),公钥关系 `s = e H^⊤`。单轮 5-pass Σ-协议(`protocol_reference.md` §4)证明"知道一个**受限** `e` 使 `e H^⊤ = s`",具备:

- **完备性(Completeness):** 诚实证明者必被接受(已由四等级端到端往返实证,§6.3)。
- **诚实验证者零知识(HVZK):** 第一应答 `y = u′ + chall1·e′` 被均匀掩码 `u′` 隐藏;开放的 `(y, v)` 或 `Seed` 不泄露 `e`。模拟器可在不知 `e` 时生成同分布转录(CROSS 规范 §证明;青鸾承诺加盐使模拟与真实在 SM3-RO 下不可区分)。
- **特殊可靠性(Special soundness):** 由两份共享 `(cmt0,cmt1,chall1)` 但 `chall2` 不同的接受转录,可**抽取**出受限 `e := v ⋆ e′ ∈ E^n` 且 `e H^⊤ = s`(`protocol_reference.md` §8 给出抽取式)。即:能让两个分支同时通过 ⇒ 知道 R-SDP 解。
- **每轮作弊概率** `≈ p/2(p−1) ≈ 1/2`;`τ` 轮**固定权重 `w`** 并行把可靠性误差压到 `≤2^{−λ}`(伪造分析见 §4)。

### 2.2 为什么 v1 的"仅凭公钥通用伪造"被根除

v1 致命缺陷:`mpc_commit` 丢弃秘密(`(void)e;`),各方份额为独立随机量,末方综合征份额取 `s−Σ(其余)`,验证仅核对"份额和 = 公开综合征"(恒成立)。故任何持 `pk=(seed_H,s)` 者可伪造。

v2 修复(代码级,`mpc.c` / `verify.c`):
1. **witness 真正进入承诺:** `mpc_commit0` 用秘密指数 `eta_sk` 计算 `v = eta_sk − eta′ (mod z)` 与 `s′ = (g^v ⋆ u′)H^⊤`,`cmt0` 绑定 `(s′,v)`(对比 v1 的 `(void)e;`)。
2. **验证核验受限关系:** `verify.c` 对 `chall2[i]=0` 分支调用 `rsdp_unpack_fz`,**逐元素检查 `v_exp[i] < z`(受限性)**;越界即拒(`verify.c:92`)。这正是 v1 缺失的"受限证明"。
3. **验证核验线性关系:** `mpc_recompute_cmt0` 重算 `s′ = (g^v ⋆ y)H^⊤ − chall1·s` 并比对承诺;`chall2[i]=1` 分支用揭示种子重建 `e′` 并验受限。
4. **常时摘要比较:** 两个 FS 摘要用 `ct_memcmp` 比较(`verify.c:105–106`)。

**防回归门禁(`test/test_forgery.c`):** 仅用 `pk`、以任意伪造 witness 复刻整签名流程,断言验证**失败**;四等级均 **26/26 伪造被拒**(§6.3)。⇒ "仅凭公钥伪造"在结构上不可能。

### 2.3 Fiat–Shamir 转换与不可伪造

把交互协议经 FS 转非交互:挑战由 `H_w` 派生(`protocol_reference.md` §6),并**绑定 `(salt, pk, μ, 全部承诺)`**:

```
digest_Msg    = H_w(DOMAIN_MSG  | Salt | pk_hash | Msg)            # 见 §3 修复
digest_cmt    = H_w(DOMAIN_DIGEST_CMT | H_w(cmt0[1..τ]) | H_w(cmt1[1..τ]))
digest_chall1 = H_w(DOMAIN_CHALL1 | digest_Msg | digest_cmt | Salt)
chall1        = XOF(DOMAIN_CHALL1_GEN | digest_chall1 | τ+c)      ∈ (F_p^*)^τ
digest_chall2 = H_w(DOMAIN_CHALL2 | y[1..τ] | digest_chall1)
chall2        = XOF(DOMAIN_CHALL2_GEN | digest_chall2 | τ+c+1)    ∈ B(τ,w)
```

- **ROM 论证:** 在 `H_w` 建模为随机预言机时,FS 把 §2.1 的可靠性转为存在性不可伪造;伪造者要么真知道 R-SDP 解(§2.1 抽取),要么只能**枚举挑战**碰运气——其代价正是 §4 的伪造攻击复杂度 `forgery_raw`。`(τ,w)` 选取使 `forgery_raw ≥` 经典目标,即便攻击者用满 `2^80` 次预言机询问(询问界已计入 §4 的 Kales–Zaverucha/Prop 7 分析)。
- **QROM:** FS 在 QROM 下有已知安全损失(多项式于询问数)。青鸾以**保守 `quantum_bits = classical/2`(全 Grover)**覆盖量子伪造搜索与量子 ISD 两侧(§4),量子达标见 §4 表;`H_w` 量子原像 `= 2^λ` 覆盖挑战派生所需的量子单向性。
- **消息绑定:** `μ=digest_Msg` 经 `salt`(eTCR 随机化子)与 `pk_hash`(公钥绑定)双重强化(§3)。

## 3. 哈希用途的归约义务(核心)

**论证义务(设计 §9.2 / R1):** 证明青鸾协议中**所有**哈希/CSPRNG 用途均可经**加盐**归约为 SM3 的 **(第二)原像 / TCR/eTCR / 伪随机性**,而**不可约地依赖朴素(生日)抗碰撞之处为空**。这是因为 `H_w` 是**多管道 SM3**(`hash.c`:`pipe_i = SM3(i ‖ m)`,拼接),由 **Joux 多碰撞**其朴素抗碰撞被封顶 `~2^128`(与宽度无关);而其**原像/第二原像随宽度增长**:多管道 `2λ` 位输出的(第二)原像 `= 2^{2λ}`(经典)/ `2^λ`(量子 Grover)。**诚实声明:`H_w` 仅声称原像/TCR 达全宽,不声称拼接提升抗碰撞**(`hash.h` 顶部已注明)。

### 3.2 FS 承诺/挑战摘要为何不依赖朴素抗碰撞

`digest_cmt*`、`digest_chall1/2` 进入挑战派生。与消息哈希(§3.3)不同,**这些摘要由签名者自选的字节确定性派生挑战**,且每轮承诺 `cmt0/cmt1` 已加盐(eTCR 绑定,等价破解 `≥2^{2λ−ε}`)。伪造者能做的是:任选 `(digest_cmt, digest_chall2)` 字节、研磨 `Salt`/承诺,直到得到一个**可作弊的**挑战——这恰是 §4 的 Prop 6/Prop 7 攻击,其代价 `forgery_raw` 为**研磨/原像式**(每次尝试 `≥1` 次哈希),已计入 `2^80` 询问界并由 `(τ,w)` 覆盖。**不存在**"找一对碰撞即免费转移签名"的结构(那只发生在消息哈希,见 §3.3)。因此这些用途是研磨/原像界,而非生日界。

> **保守备选(已记录,当前不需要):** 若未来更紧的 QROM 分析要求某摘要具备朴素抗碰撞,设计 §5.1 的 **SHAKE-256/SHA3-512 回退**可定点替换该处而不动其余(纯 SM3 仅在该点让位)。修复消息哈希后,EUF-CMA 论证**不触发**该回退。

### 3.3 消息哈希(修复点)与 `pk_hash`

- **消息哈希 `digest_Msg`:** 这是**唯一**会因哈希碰撞直接产生 EUF-CMA 伪造的点——若 `Msg≠Msg′` 碰撞,签名可在两消息间转移。修复前未加盐 ⇒ 依赖朴素抗碰撞(`2^128` 封顶);**修复后** `digest_Msg=H_w(DOMAIN_MSG|Salt|pk_hash|Msg)`:`Salt` 每签名新鲜且仅随签名公开,攻击者无法离线预算碰撞;在 EUF-CMA 中攻击者拿到含 `Salt` 的签名后,要在该 `Salt` 下找消息伙伴即**第二原像** `=2^{2λ}`(Joux 不破第二原像);跨 `≤2^80` 签名(《技术要求》(2)的询问上界)的**多目标第二原像** `≈2^{2λ−80}`。各等级 `2^{2λ−80}=`176/432/688/944 `≥` 经典目标 128/256/384/512 ✓;量子多目标 `≈2^{λ−40}=`88/216/344/472 `≥` 量子下限 80/128/192/256 ✓。
- **`pk_hash`(BUFF 公钥绑定):** `digest_Msg` 含 `pk_hash` 把签名绑定到公钥(消息–密钥绑定 / 抗"密钥替换")。**对 EUF-CMA 不构成抗碰撞依赖**:验证用**实际 `pk` 字节**展开 `(H,s)`,即便两公钥 `pk_hash` 碰撞也不影响对固定目标 `pk` 的不可伪造性。**残留(R6):** 完整 BUFF "排他所有权"在 `>128` 级若要严格成立,需 `pk_hash` 抗碰撞(多管道 SM3 仅 `2^128`)——此属 EUF-CMA 与《技术要求》功能项**之外**的加强性质;如需,可对 `pk_hash` 定点启用 SHAKE-256(§3.2 备选)。已如实标注,不夸大。

## 4. 具体安全表(经典 / 量子)

数值来源 `rsdp_estimator.py`(自校验复现 CROSS Table 5/7,详见 `parameters.md` §2–§3)。**绑定安全 = min(密钥恢复, 伪造)**;`(n,k,τ,w)` 不受 §3 修复影响(修复仅改哈希输入,不改维度)。

| 等级 | 密钥恢复 C/Q | 伪造 raw C/Q | **绑定 C/Q** | `H_w` 原像 C/Q | 消息 eTCR(多目标)C/Q | 目标 C/Q | 结论 |
|---|---|---|---|---|---|---|---|
| QingLuan-128 | 143 / 72 | 128.8 / 64.4 | **129 / 64** | 256 / 128 | 176 / 88 | 128 / 80 | ✓ 注① |
| QingLuan-256 | 274 / 137 | 257.2 / 128.6 | **257 / 129** | 512 / 256 | 432 / 216 | 256 / 128 | ✓ |
| QingLuan-384 | 400 / 200 | 384.3 / 192.2 | **384 / 192** | 768 / 384 | 688 / 344 | 384 / 192 | ✓ |
| QingLuan-512 | 528 / 264 | 512.1 / 256.1 | **512 / 256** | 1024 / 512 | 944 / 472 | 512 / 256 | ✓ |

- **冗余:** 经典绑定均 `≥` 目标(128 级 +1,256 级 +1,384/512 持平至 +16);伪造侧另有约 5 比特"未领 +5 信用"冗余(`parameters.md` §2.1);ISD 量子侧为悲观平方根,留隐藏冗余;`H_w` 原像/eTCR 均远超目标。
- **注①(128 级量子 80):** 绑定量子 64(=128/2 全 Grover)按 **NIST 类别 1**(AES-128 有限深度 Grover,实际远高于 `2^64`)等价满足,与"128→80"比值一致;消息 eTCR 量子 88 与 `H_w` 量子原像 128 均 `≥80`(已按《技术要求》(2)的 `≤2^80` 询问上界重算)。若需裸量子 `≥80`,按 `parameters.md` §4.1 注①一档上调码参数。

## 5. 抗量子组件审查

- 全部公钥运算建立在 **R-SDP**(受限综合征译码,NP 完全,无已知有效量子算法;最优攻击 = ISD,仅得 Grover 平方根加速,已计入 §4)。
- **不含** RSA / 整数分解、椭圆曲线 / ECDH / ECDSA、有限域 DH / DLP 等 Shor 可破组件;无配对、无格 trapdoor、无隐藏子群结构。
- 对称面:仅 **SM3**(及其计数器模式 XOF、Hash-DRBG)。量子威胁为 Grover(原像 `2^{n/2}`)与碰撞(`~2^{n/3}`/Brassard);青鸾经 `H_w` 加宽至 `2λ` 位并**仅依赖原像/eTCR**(§3),量子原像 `2^λ ≥` 量子下限;朴素抗碰撞不被依赖,故 Grover/BHT 对碰撞的加速不影响安全声明。
- 随机性:SM3 Hash-DRBG(GM/T 0005);确定性种子注入 `drbg_seed` 仅用于 KAT 复现,不降熵(`utils.c`)。

## 6. 其他安全特性与工程保证

### 6.1 抗侧信道(常时实现,设计 §10)
- 受限集运算 `restr_val/restr_exp_add/sub` 常时查表 + 掩码,无秘密相关分支/索引(`restr.c`)。
- `F_p` 算术用 Barrett 约简,无数据相关除法(`fq_arith.c`)。
- 摘要比较用 `ct_memcmp`(`verify.c:105–106`);秘密缓冲 `secure_zero`(编译器屏障)清零(`sign.c` cleanup)。
- 错误处理:分配/熵失败即清零返回错误码,绝不以陈旧状态产出密钥/签名(`sign.c`/`keygen.c`)。

### 6.2 消息/公钥绑定、多目标/多用户、长消息/多签名
- **消息绑定 + 公钥绑定:** `digest_Msg` 含 `Salt`(eTCR)与 `pk_hash`(BUFF),见 §3.3。
- **多目标/多用户:** 每签名 `Salt` 取 `2λ` 比特;`≤2^80` 签名询问下多目标 eTCR/原像裕度满足各等级(§3.3、§4)。
- **`2^63` 比特消息:** 消息经 `hash_update` 流式吸收,SM3 长度域 64 位,支持 `≥2^63` 比特。
- **`2^64` 次签名:** 每签名独立 `Salt`(`2^{2λ}≥2^256` 盐空间),反序列化对全部长度/范围边界校验并拒畸形签名(`verify.c`:`siglen`/`rsdp_unpack_fz` 校验)。

## 8. 残留风险与开放项

- **R1(已闭环):** "全部哈希用途归约为 TCR/原像"——消息哈希未加盐缺陷已修复(§0 ★、§3.3),EUF-CMA 不再依赖朴素抗碰撞;不触发 SHAKE 回退。
- **R2(384/512 外推):** `(n,k)` 为 CROSS Table 5 线性外推(~15 比特余量);**标准化前须用官方 CROSS 估算器复核**(`parameters.md` §8)。
- **R3(128 级量子):** 已按 NIST 类别 1 满足(§4 注①);若要裸量子 ≥80 则上调码参数。
- **R6(完整 BUFF,EUF-CMA 之外):** `>128` 级的"排他所有权"严格性需 `pk_hash` 抗碰撞;当前不在 EUF-CMA / 功能要求内,如需可对 `pk_hash` 定点启用 SHAKE-256(§3.3)。
- **R5(签名尺寸):** MPCitH 固有偏大(18 KB–286 KB);压缩(种子树/Merkle)与多平台优化属第 2 部分。
