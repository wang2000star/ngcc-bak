## 1. 困难问题与固定代数

青鸾 v2 实例化 **CROSS-RSDP**(受限综合征译码),所有等级共用同一基域与受限集:

| 量 | 值 | 含义 |
|---|---|---|
| `p` | 127 | 素域 `F_p` 阶 |
| `g` | 2 | 受限乘法子群生成元 |
| `z` | 7 | 受限集阶 `|E|`,`E = ⟨2⟩ = {1,2,4,8,16,32,64} ⊂ F_p^*`(`z | p−1`) |
| `k/n` | ≈ 0.596 | 码率(由 CROSS Table 5 锚点拟合) |

困难问题 **R-SDP**:给定 `H ∈ F_p^{(n−k)×n}` 与 `s ∈ F_p^{n−k}`,求受限错误 `e ∈ E^n` 使 `e H^⊤ = s`(NP 完全)。等级仅由 `(n, k, t, w)` 区分。

## 2. 安全估算方法学

参数集的安全 = 两个**独立**代价模型的**最小值**(`min`):

### 2.1 签名伪造(Fiat–Shamir 可靠性)

忠实复现 CROSS round-2 规范 §3.2 的两个伪造攻击:

- **Proposition 6**("第一伪造"):`prop6_bits(t,w)`;
- **Proposition 7**("第二伪造",即 Kales–Zaverucha 攻击,按固定权重优化,见 eprint 2025/127):`prop7_bits(t,w)`,**这是真正的绑定攻击(binding attack)**。

报告 `forgery_raw = −log2(P_success) = log2(#伪造尝试)`,每次尝试**至少一次哈希调用**。按 CROSS 约定每"操作" `2^5` 条指令(`+5`)即可精确复现 CROSS Table 7 的 128/192/256 类别(见 §3 自校验)。**青鸾在选参时不领取这 `+5` 信用**,故每个等级的轮数自带约 5 比特伪造冗余(满足《算法技术要求》安全冗余条目)。

### 2.2 密钥恢复(求解 R-SDP)

已知最优密码分析 = 带表示法(representation)与错误集平移的组合式 ISD。复现该优化需 CROSS "安全指南",超出本估算器范围,故**锚定 CROSS round-2 Table 5**("shifted representations",已公布的最低/最优攻击)并标定一个线性(关于 `n`)模型:

```
n=127 → 143 bit,   n=187 → 207 bit,   n=251 → 274 bit
```

并打印一个**可计算的碰撞搜索下界**(collision-LB)作为合理性旁证。新等级(384/512)为线性外推,**标准化前必须用官方 CROSS 估算器复核**。

### 2.3 量子模型(保守)

对**两个**度量均取 `quantum_bits = classical_bits / 2`(对伪造搜索与 ISD 搜索都施加全 Grover 平方根加速)。其中 ISD 一侧对防御方是**悲观**的——真实量子 ISD 增益远小于平方根,留有隐藏冗余。入门等级 80 比特量子下限高于 `128/2 = 64`,按 **NIST 类别 1**(AES-128 在有限深度 Grover 下)等价给出,叠加上文伪造冗余。

### 4.1 安全达标核验

| 等级 | 经典目标 | 密钥恢复(经典/量子) | 伪造 raw(经典/量子) | **绑定安全 = min(经典/量子)** | 量子下限 | 达标 |
|---|---|---|---|---|---|---|
| QingLuan-128 | 128 | 143 / 72 | 128.8 / 64.4 | **129 / 64** | 80 | ✓ 经典 129≥128;量子见注① |
| QingLuan-256 | 256 | 274 / 137 | 257.2 / 128.6 | **257 / 129** | 128 | ✓ 经典 257≥256;量子 129≥128 |
| QingLuan-384 | 384 | 400 / 200 | 384.3 / 192.2 | **384 / 192** | 192 | ✓ 经典 384≥384;量子 192≥192 |
| QingLuan-512 | 512 | 528 / 264 | 512.1 / 256.1 | **512 / 256** | 256 | ✓ 经典 512≥512;量子 256≥256 |

- **#sol(期望解数):** 128→2.08,256→1.43,384→1.17,512→1.02(`1 + (z^n−1)·p^{k−n}`),均接近 1,无显著多解弱化。
- **冗余:** 各等级经典绑定安全均 `≥` 目标且带 ≥0.1–16 比特余量;伪造侧另有 §2.1 的 5 比特"未领信用"冗余;ISD 量子侧为悲观平方根,留隐藏冗余。

> **注①(128 级量子 80):** 128 级绑定量子位为 64(= 128/2 全 Grover)。(注:此处“80”指**等级量子下限**,与《技术要求》(2)允许的 `≤2^80` **签名询问预算**是两个不同的量,勿混淆。)该 80 比特下限按 **NIST 类别 1** 口径满足:NIST 将 AES-128(在**有限深度** Grover 下,因 MAXDEPTH 约束实际远高于 2^64)定为类别 1 安全。青鸾-128 的经典 129 比特对应同一类别 1 强度,与《算法技术要求》"128→80"的比值一致;另叠加伪造侧 5 比特冗余。若评估方要求量子位"裸值" ≥80,可一档上调至 QingLuan-192/256 码(`n=187`,密钥恢复经典 207 / 量子 103)。

## 5. 变体(fast / small)与当前发布范围

- **设计目标(design §7.1)** 要求每等级三变体(均衡 / 快速 / 小签名),通过调节 `(t, w)` 在"尺寸 ↔ 速度/轮数"上折中。
- **当前实现发布** 每等级**一套均衡变体**(共 4 套),即上表;`params.h` 暂未引入 `QL_VARIANT_{BAL,FAST,SMALL}` 选择宏。
- **方法学已支持变体生成:** 估算器 `--search` 模式在小签名区(`w/t ≥ 0.6`)实时扫描 `(t, w)`,对同一 `(n,k)` 给出"轮数 `t` ↑ → 签名 `sig` ↓、但每签名哈希次数 ↑"的真实权衡曲线(扫描窗口见 `rsdp_estimator.py` 的 `SCAN` 字典;`--search` 实跑该扫描,因 Prop 7 代价计算较重,数分钟级,选参时一次性运行)。把任一扫描点的 `(t,w)` 填入 `params.h` 对应等级即得一个 small 变体;减小 `t`(放宽到 `w≈t/2` 高签名角,需扩展搜索窗)得 fast 变体。
- **结论(诚实声明):** 三变体目录为**已记录的后续扩展**,其参数须由 `--search` 产出并经 §4.1 同样的达标核验后方可发布,**本文档不预先编造 fast/small 的具体数值**。

## 6. `Hw` 宽度、盐长与多目标/长消息

- `Hw`(加宽哈希,见 `hash.c` 多管道 SM3)输出 `2λ` 比特:128/256/384/512 → **256/512/768/1024 位**;`HASH_PIPES = ⌈2λ/256⌉ = 1/2/3/4`。
  - **诚实安全声明:** `Hw` 仅声称**原像 / 第二原像 / TCR** 抗性达其全宽(经典 `2λ`,量子 `λ`);**不**声称拼接提升朴素抗碰撞(Joux 多碰撞)。各等级原像安全(经典 `2λ` ≥ 目标 `λ`;量子 `λ` ≥ 量子下限)绰绰有余。详见 `security-argument.md` §哈希。
- **盐 / 随机化子** `salt`、`master_seed`、`keyseed` 均取 `2λ`/`λ` 比特;**消息绑定 `digest_Msg = Hw(DOMAIN_MSG | salt | pk_hash | Msg)` 用每签名 `salt` 作随机化子**,使其依赖**多目标 eTCR / 第二原像**(`2^{2λ−80} ≥` 目标)而非朴素抗碰撞——这对多管道 SM3 是**必需**的(否则消息碰撞 `2^128` 可转移签名,封顶 256/384/512;详见 `security-argument.md` §3)。在仅依赖 TCR/原像前提下,`2λ` 比特盐使 `≤2^80` 次签名询问(《技术要求》(2)上界)下多目标裕度满足对应等级。
- **长消息:** 消息经 `hash_update` 流式吸收,长度计数为 64 位(`uint64_t`),支持 `2^63` 比特消息;一对密钥可签 `≥2^64` 次(盐空间 `2^{2λ} ≥ 2^256`)。

## 7. 尺寸推导与实测核对

`include/params.h` 的尺寸宏(fast 风格直接发送布局,`H=[V|I]`):

```
syndrome_bytes = ⌈r·7/8⌉                         # s 打包(7 bit/元素)
y_bytes        = ⌈n·7/8⌉                         # y 打包(F_p)
v_bytes        = ⌈n·3/8⌉                         # v 打包(F_z 指数,3 bit/元素)
|sk| = 2λ/8                                       # = keyseed
|pk| = 2λ/8 + syndrome_bytes                      # Seed_pk || pack(s)
|sig| = salt + 2·Hw + w·seed + w·Hw + (t−w)·(y_bytes + v_bytes + Hw)
```

下表 **估算器值 = 编译运行实测值**(`gcc -O2 -DQINGLUAN_<L>`,`test/main.c` 打印),逐字节一致:

| 等级 | `|pk|` | `|sk|` | `|sig|` | 签名 (`main.c` 实测) | 单次签名耗时(参考) |
|---|---|---|---|---|---|
| QingLuan-128 | 77 B | 32 B | 18 720 B | 18 720 B ✓ | ~77 ms |
| QingLuan-256 | 153 B | 64 B | 74 248 B | 74 248 B ✓ | ~0.23 s |
| QingLuan-384 | 227 B | 96 B | 164 940 B | 164 940 B ✓ | ~0.42 s |
| QingLuan-512 | 302 B | 128 B | 292 816 B | 292 816 B ✓ | ~0.87 s |

> 性能为单线程 MinGW GCC 15.2 `-O2` 参考值;较 v1(2.7 s–139 s)已从秒级降至毫秒/亚秒级。MPCitH 签名固有偏大(数十–数百 KB);进一步压缩(种子树 / Merkle 树)与多平台优化属第 2 部分范围。

## 8. 风险与复核义务

- **R2(384/512 外推):** `(n,k)` 为 CROSS Table 5 线性外推,带约 15 比特密钥恢复余量;**标准化前必须以官方 CROSS 估算器复核**(本文与代码注释均已标注)。
- **R3(128 级量子):** 已按 NIST 类别 1 口径满足(§4.1 注①);若评估方要求裸量子位 ≥80,按注①一档上调。
- **复现:** 上述全部数字可由 `python rsdp_estimator.py`(自校验 + 推荐阶梯)与 `--search`(权衡曲线)重现;尺寸可由各等级编译 `test/main.c` 复核。
