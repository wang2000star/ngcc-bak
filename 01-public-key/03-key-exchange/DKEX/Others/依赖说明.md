# DKEX 依赖说明 / Dependency Statement（PKCKEX-359777）

## 1. 第三方库依赖
ML-DSA（FIPS 204）数字签名原语 —— 采用 **pq-crystals/dilithium** 参考实现（ref 目录），**未经修改**；上游许可证：public domain / Apache-2.0（双许可）；用途：DKEX 握手中的数字签名；经 `adkex_sig.h` 可插拔签名接口调用，**可替换为任意符合要求的后量子签名**。属标准化第三方构件，非本提案原创。

## 2. 官方提供文件（ICCS API_PKC，非第三方依赖，逐字节未修改）
`drng.c` / `drng.h`、`auxfunc.c` / `auxfunc.h`、`KAT_KEX.c`。
（杂凑/XOF 全部经官方 `auxfunc` 的 SM3：`sm3hash` / `pseudoXOF` / `pseudohash`，`DKE_HASH=0`。）

## 4. 说明
除上述官方 API_PKC 文件与 ML-DSA 参考实现外，本算法**无需链接任何其它第三方密码库**；NTT/多项式优化汇编的出处与权属按平台区分：

- **x86-64 AVX2**（`avx2-linux/`）：DKE 自然序 NTT 汇编（`ntt256/512`、`invntt256/512`、`basemul`、`basemul512`、`poly_ops` 等）为提案组成员 Liu Rui（刘锐）原创、属 B.3 原创权属范围；其中 `*_dkek_*.S` 与 `ntt_tobytes_avx2.S` 为 pq-crystals ML-KEM 移植，与其余 AVX2 底层构件（pq-crystals / PQClean）同属外部第三方、不在 B.3 范围（见第 5 节）。
- **arm64 NEON**（附加实现 `aarch64-native/` 的 NTT 汇编）：改编自 mlkem-native 项目（Arm Limited / Hanno Becker / Amin Abdulrahman / Matthias Kannwischer 等，Apache-2.0 OR ISC OR MIT），属外部第三方、**不在 B.3 原创权属范围内**，上游作者保留著作权。
- **Cortex-M4 Plantard+matacc**（附加实现 `cortex-m4/` 汇编）：提案组成员 Junhao Huang（黄俊豪）的成果（ePrint 2022/956，Apache-2.0），属提案组原创、在 B.3 范围内。

各第三方构件均在源码文件头部内联标注出处；许可证一览见下文第 6 节。

# DKEX Dependency Statement (English) — PKCKEX-359777

## 1. Third-party library dependencies
ML-DSA (FIPS 204) digital-signature primitive — uses the **pq-crystals/dilithium** reference implementation (the `ref` directory), **unmodified**; upstream license: public domain / Apache-2.0 (dual-licensed); purpose: the digital signature in the DKEX handshake; invoked through the pluggable signature interface `adkex_sig.h`, and **replaceable by any conforming post-quantum signature**. It is a standardized third-party component, not original to this submission.

## 2. Official files provided by ICCS (API_PKC; NOT third-party; byte-for-byte unchanged)
`drng.c` / `drng.h`, `auxfunc.c` / `auxfunc.h`, `KAT_KEX.c`.
(All hashing / XOF go through the official `auxfunc` SM3: `sm3hash` / `pseudoXOF` / `pseudohash`, with `DKE_HASH=0`.)

## 3. Toolchain and runtime environment versions
| Component | Version |
|-----------|---------|
| GNU gcc (x86-64 / aarch64 Linux) | 13.3.0 |
| Apple clang (macOS, supplementary cross-check) | bundled with macOS 15 |
| arm-none-eabi-gcc (Cortex-M4) | 14.2.1 |
| qemu-system-arm (Cortex-M4 testing) | system package |
| Build system | bash + per-instance build.sh |
| Operating system | Ubuntu 24.04 / macOS 15 |

## 4. Notes
Apart from the official API_PKC files listed above and the ML-DSA reference implementation, this implementation **needs no other third-party cryptographic library to be linked**. The NTT / polynomial optimization assembly is attributed by platform:

- **x86-64 AVX2** (`avx2-linux/`): the DKE-specific natural-order NTT assembly (`ntt256/512`, `invntt256/512`, `basemul`, `basemul512`, `poly_ops`, etc.) is original work by proposal-team member Liu Rui（刘锐）, within the B.3 ownership scope; the `*_dkek_*.S` and `ntt_tobytes_avx2.S` files are ports of pq-crystals ML-KEM, and the other low-level AVX2 building blocks are from public third-party code (pq-crystals / PQClean) — all external third-party, OUTSIDE B.3 (see Section 5).
- **arm64 NEON** (the `aarch64-native/` NTT asm under Additional_Implementation): adapted from the mlkem-native project (Arm Limited / Hanno Becker / Amin Abdulrahman / Matthias Kannwischer et al., Apache-2.0 OR ISC OR MIT). This is external third-party code, OUTSIDE the scope of the B.3 ownership statement; the upstream authors retain copyright.
- **Cortex-M4 Plantard+matacc** (the `cortex-m4/` asm under Additional_Implementation): work by proposal-team member Junhao Huang (ePrint 2022/956, Apache-2.0), original to the proposal team and within the B.3 scope.

Each third-party component is attributed inline at the top of its source file; the licenses are summarized in Section 6 below.
