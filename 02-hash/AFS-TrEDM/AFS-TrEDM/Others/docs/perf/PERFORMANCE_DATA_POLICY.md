# Performance Data Policy

Stage16 performance tables use fresh live benchmark runs.

## Fresh Live Tables

The official Stage10 live performance outputs are produced by:

```bash
bash scripts/run_live_perf_tables_s6.sh \
  --root /home/weibh/Codex/AFS-TrEDM_Submission_v2.0 \
  --mode full \
  --instances 512,768,1024 \
  --include-sha3 \
  --include-sha3-reference
```

That script builds and executes the requested hash implementations during the run. It writes fresh execution logs under `/tmp/afs_tredm_s6/live_perf/<run_id>/` by default and fresh CSV/Markdown output under `docs/perf/live/<run_id>/`, with `/tmp/afs_tredm_s6/live_perf/latest/` and `docs/perf/live/latest/` views.

## Metric Classes

Single-message latency/throughput rows are directly measured by calling one hash operation per iteration. The Stage16 single-message AFS rows are Reference, optimized opt64, and optimized AVX2 hybrid for each selected AFS-TrEDM-S6 instance.

Batch16 AVX512 true is a multi-buffer normalized throughput backend. Its cycles/byte and MB/s values are normalized over all messages in a 16-message batch, and its latency value is normalized per message across that batch. It must not be described as single-message latency.

## SHA3-512 Baselines

OpenSSL EVP SHA3-512, SHA3-512 Reference C, and CompactFIPS202 SHA3-512 rows in Stage16 live tables are produced by fresh benchmark drivers in `tools/perf/baselines/`. They must not be generated by reading old CSV files.
